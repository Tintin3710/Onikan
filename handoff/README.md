# Handoff: Onikan (오니칸) — 일본어 단어 학습 앱 확정 5화면

## Overview

Onikan은 출퇴근·자투리 시간에 일본어 단어/한자를 학습하는 모바일 앱이다. 하루치 단어를 학습하면 '오니기리 재료'를 하나 받고, 재료 4개가 모이면 레시피(오니기리 1종)가 완성되어 도감에 수집된다. 복습 스케줄은 FSRS(간격 반복)가 관리한다.

타겟은 30–40대 직장인. 톤은 "깔끔하고 믿음직한 데일리 리추얼"이며, 귀여움은 마스코트·재료·오니기리 일러스트로만 표현하고 UI 자체는 무채색 중심으로 조용하게 유지한다.

확정된 5개 화면:

| # | 화면 | 확정안 |
|---|---|---|
| 1 | 홈 | `10a` — 오늘 학습 / 회독 세그먼트 + 탭 가능한 진행 카드 |
| 2 | 학습 세션 | `1b` — 리콜 흐름 + 2단계 평가 |
| 3 | 학습 완료 결과 + 영수증 | `2a` 레이아웃 + `7a` 영수증 발행 |
| 4 | 메뉴(도감) | `5a` — 목록 ↔ 그리드 전환 |
| 5 | 레시피 상세 | `8a` — 재료 4개 체크리스트 |

기술 스택은 Expo · React Native를 전제로 한다.

## About the Design Files

이 번들의 `Onikan Study.dc.html`은 **HTML로 만든 디자인 레퍼런스**다. 의도한 외형과 동작을 보여주는 프로토타입이며, 그대로 가져다 쓰는 프로덕션 코드가 아니다.

해야 할 일은 이 HTML 디자인을 **Expo · React Native 환경에서 그 환경의 관례와 라이브러리로 다시 만드는 것**이다. HTML/CSS를 복사하지 말고, `View`/`Text`/`Pressable`/`FlatList`와 프로젝트의 기존 컴포넌트·테마 시스템으로 재구성한다.

파일을 열면 여러 개의 아이폰 프레임이 나열되어 있다. 각 프레임 왼쪽 위 배지가 이 문서의 안 번호와 대응한다. 확정 배지는 `10a` `1b` `2a` `7a` `5a` `8a` 여섯 개이고, **그 외 배지(`1a` `2b` `3a` `3b` `4a` `4b` `7b` `9a`)는 검토 과정의 대안이므로 구현 대상이 아니다** — 판단 근거를 확인할 때만 참고한다.

프레임 오른쪽의 회색 패널은 각 안의 설계 의도를 적은 주석이다. "왜 이렇게 되어 있는가"를 알고 싶을 때 읽으면 된다.

상단 "다크 모드 보기" 버튼으로 라이트/다크를 전환할 수 있고, 각 프레임은 실제로 탭·전환이 동작한다.

## 인터랙션 프로토타입 — 재료 노출 · 기록 (추가)

확정 5화면과 별개로, 두 개의 인터랙션을 동작하는 프로토타입으로 정리해 [`interactions/`](./interactions)에 두었다. **이 두 화면은 위 `Onikan Study.dc.html` 캔버스에는 들어 있지 않다** — 캔버스는 Figma에서 내보낸 런타임 문서라 손으로 화면을 끼워 넣기 어려워, 별도 프로토타입으로 만들었다. 캔버스에 합치려면 Figma에서 만들어 다시 내보내야 한다.

| 파일 | 내용 |
|---|---|
| [`interactions/onikan-interactions.html`](./interactions/onikan-interactions.html) | 동작하는 프로토타입. 브라우저에서 바로 열린다. 상단에서 **화면 전환 · 라이트/다크 · 다시 재생** |
| [`interactions/MOTION.md`](./interactions/MOTION.md) | 모션 스펙 — 타임라인 · 이징 · 카운트업 · 색 사용 규칙 · `나` 마커 배치 규칙 |

폰트·재료 이미지는 이 번들의 자산을 상대경로로 참조한다(`../_ds/.../fonts`, `../ingredients/rice.png`). HTML 한 파일만 떼어 옮기면 이미지·폰트가 깨지므로 `handoff/` 폴더 구조를 유지한 채 연다. 색·타이포·간격은 이 문서의 토큰을 그대로 따른다.

### A. 재료 노출 (학습 완료)

**화면 3(결과 `2a`+`7a`)의 보상 릴리즈 모먼트를 확장한 것이다.** 위에 적힌 결과 화면의 3종 애니메이션(`riseIn`/`pop`/`limefade`)을 이어받아, 재료 아트 팝인 → 라임 체크 배지 + **링 펄스 1회 + 소수의 스파크**(콘페티가 아니라 절제된 표현) → 진행 칸이 라임으로 채워졌다 잉크로 정착 → 단어 수 카운트업 → CTA 슬라이드업 순으로 조율한다. 정확한 딜레이·이징 값은 `MOTION.md` 참고.

### B. 기록 탭 (신규 제안)

**이 문서에서 줄곧 "아직 설계되지 않음"으로 남아 있던 기록 탭의 한 방향 제안이다.** 앞서 적힌 방향(영수증을 날짜순으로 쌓는 아카이브, `7b` 스케치)과는 **다른 접근** — 테스트 점수 · 연속 학습(스트릭) · 스탯 타일 · 점수 분포를 한 화면에 모은 **통계형 기록**이다. 확정이 아니라, 영수증 아카이브를 대체하거나 함께 검토할 대안으로 본다.

- 구성: 닫기 + 라지 타이틀 `기록` → 테스트 점수 카드 → 연속 학습(불꽃 + 요일 체크, 유지한 날만 라임) → 스탯 타일 2×2 → 점수 분포 곡선 + `지금 연습하기`(화면 유일 오렌지)
- 인터랙션: **라지 타이틀 → 상단 인라인 타이틀 축소**(스크롤 스크럽), 숫자 카운트업, 분포 곡선 왼→오 드로잉, 스트릭 체크 순차 팝인

**`on-primary`가 흰색이 아닌 이유:** 흰 글자를 orange-600 위에 올리면 3.56:1로 AA(4.5:1)에 미달한다. CTA 라벨은 18px/600이라 large text 기준(24px 또는 18.66px bold)에도 못 미쳐 4.5:1이 그대로 적용된다. 잉크로 바꾸면 4.72:1이 되고, 다크 모드는 원래부터 잉크였으므로 이 토큰이 양 모드에서 일관해진다. **브랜드 오렌지 `#EA580C`는 그대로다.** `primary`를 orange-700로 어둡게 하는 대안은 `tab-active`와 같은 색이 되어 버려 기각했다.

**`plate`가 테마 고정인 이유:** 마스코트·재료·오니기리 일러스트가 검정 선화라 다크에서 배경까지 어두워지면 그림이 사라진다. 흰 선화 버전 에셋이 준비되면 그때 테마별로 전환한다.

**`tab-active`가 테마별로 다른 이유:** 12px 라벨이 AA(4.5:1)를 넘어야 해서 라이트는 orange-700 `#C2410C`(4.63:1)를 쓴다. 다크는 `#EA580C`가 5.21:1로 통과한다.

**`bar-fill`이 잉크가 아닌 이유:** 홈·메뉴·상세의 진행바는 '탐색 중 참고 정보'라 잉크로 칠하면 히어로 요소와 무게가 겹친다. 단 **결과 화면(2a/7a)의 진행바만 잉크**를 쓴다 — 보상 순간이라 여기서만 강한 게 맞다.

### 컬러 사용 규칙 (엄수)

- **화면당 orange는 정확히 하나.** 주요 액션에만. 탭바의 활성 표시는 '위치 표시'로 간주해 예외로 허용한다. 오버레이가 뜨면 아래 CTA를 **렌더하지 않는다**(투명도로 가리지 말 것).
- **lime `#A3E635`는 보상 획득 순간에만.** 체크 배지, 방금 채워진 진행 칸의 페이드아웃. 그 외 어디에도 쓰지 않는다.
- **`mute`는 잠김·플레이스홀더 전용.** 일반 캡션에 쓰면 대비 미달이다. 조용하게 보이고 싶으면 색이 아니라 크기·굵기로 낮춘다.
- 금지: 그라데이션, 텍스트 그림자, 카드 안 카드(중첩), 뱃지·라벨에 브랜드색.

- 반경: 카드 **24px**, 타일 12–18px, 버튼·필·진행바 **999px**, **영수증만 4px**

   - 잠긴 행은 인덱스·이름도 `mute`, 이름은 `???`
8. **그리드 뷰** — 3열, gap 12px, `align-content:start`
   - 각 셀: 정사각 타일(`aspect-ratio:1`, radius 18px) + 라벨 14px/600, gap 8px
   - 만드는 중: 배경 `plate`, **오니기리 이미지 70×70**, `inset 0 0 0 2px #1D1D21`, 라벨 = 이름
   - 완성: 배경 `plate`, **오니기리 이미지 70×70**, 라벨 = 이름
   - 잠김: 배경 투명, `inset 0 0 0 1.5px var(--pressed)`, 가운데 "?" 22px/700 `mute`, 라벨 = 인덱스 `mute`

**설계 근거**

- **상태를 색이 아니라 형태로 구분한다.** 완성 = 라벨/실물 타일, 만드는 중 = 진행도 + 2px 잉크 테두리, 잠김 = ??? + hairline 링. 다크에서도 동일하게 읽힌다.
- **도감에도 주요 행동이 하나 있다.** 수집 화면은 보통 '볼 것만 있고 할 것이 없다'. 맨 위 카드의 "이어서"가 학습으로 돌아오는 길을 만든다.
- **리스트를 카드로 감싸지 않는다.** 흰 카드는 "만드는 중" 하나뿐이라 시선이 거기서 시작한다.
- **뷰 전환은 세그먼트가 아니라 아이콘 하나다.** 되돌리기 쉬운 조작이라 현재 상태를 두 칸으로 보여줄 필요가 없다. 선택은 기기에 저장하고 다음 진입 시 복원한다.
- **인덱스는 두 자리(`01`–`24`).** 전체가 24종이므로 세 자리는 불필요한 자릿수다.
- **목록/그리드 마지막 줄이 화면 아래에서 잘리는 것은 의도다** — 스크롤 여지를 보여준다.

### 5. 레시피 상세 (`8a`)

**Purpose.** 홈 진행 카드 또는 메뉴 항목을 탭했을 때 열리는 2depth. 어떤 재료가 모였고 다음이 무엇인지 보여주고, 학습으로 돌려보낸다.

**Layout.** 상단 내비 → 좌우 20px 본문.

1. **상단 내비** (`padding: 8px 12px 0`) — 44×44 뒤로 셰브론(`ink`) + 가운데 "ONIGIRI" 15px/600 `body` letter-spacing 1.4px (오른쪽 44px 패딩으로 광학 중앙 정렬)
2. 12px
3. 인덱스 "01" 13px/500 `body` tabular-nums letter-spacing 1.4px
4. 4px → 제목 행: "참치마요" 32px/700 ↔ "1 / 4" 15px/600 `body`
5. 20px
6. **요약 카드** — `canvas`, radius 24px, `0 6px 14px shadow`, padding `22px 20px`, 가로 flex gap 18px
   - 88×88 타일(radius 18px, `plate`, 오니기리 이미지)
   - 가운데 열 gap 10px: 오버라인 "만드는 중" / 4칸 진행바(height 6px, gap 6px, 채움 `#71717A`) / "완성까지 세 번 남았어요" 15px `body`
7. 28px → 오버라인 "재료 4" → 4px
8. **재료 리스트** — 각 행 min-height 68px, 아래 1px `pressed`, 가로 flex gap 14px
   - **받은 재료:** 44×44 타일(radius 12px, `plate`, 재료 이미지 38×38) + 이름 18px/600 `ink` + 오른쪽 "받았어요" 13px/600 `body`
   - **다음 재료:** 44×44 **hairline 링 + "?"**(투명 배경, `inset 0 0 0 1.5px var(--pressed)`, "?" 18px/700 `body`) + 이름 18px/600 `body` + 오른쪽 "다음" 필(13px/600, 배경 `soft`, radius 999px, padding `6px 12px`)
   - **미획득 재료:** 같은 링 썸네일 + 이름 18px/600 `mute`, 오른쪽 비움
9. `margin-top:auto`
10. **다음 보상 행** — 52×52 타일(radius 16px, `plate`) + 오버라인 "다음 보상" / "김 · 오늘 학습을 마치면" 18px/600, gap 14px, 아래 패딩 20px
11. **CTA** 전체폭 56px `primary` "오늘 학습 시작" → 28px

**설계 근거**

- **막다른 화면을 만들지 않는다.** 하단의 "오늘 학습 시작"이 "다음 재료를 받는 유일한 방법"으로 곧장 이어진다. 이 화면의 유일한 오렌지.
- **잠긴 재료는 그림을 감춘다.** 썸네일은 hairline 링 + "?"로 통일하고 일러스트를 노출하지 않는다 — 무엇을 받게 되는지 그림으로 미리 보여주지 않고, 이름만 남겨 순서만 알려준다. 메뉴 그리드의 잠긴 타일과 같은 부품.
- **NEXT REWARD를 카드에서 해제했다.** 회색 박스로 두면 카드 안 카드가 된다. 마스코트 인사와 같은 자리·같은 형식(썸네일 + 두 줄)으로 내려 홈과 리듬을 맞췄다.
- **영문 라벨을 한국어로.** TUNA MAYO / IN PROGRESS / INGREDIENTS → 참치마요 / 만드는 중 / 재료 4. 상단 ONIGIRI만 브랜드 워드마크로 남긴다.
- **뒤로는 44pt 셰브론만.** '＜ 뒤로' 알약은 iOS 관례와 어긋나고 폭을 낭비한다.

**참고 — 완성(4/4) 상태는 아직 설계되지 않았다.** 재료 4개가 모두 실명으로 펼쳐지고 완성 오니기리가 도감에 편입되는 화면이 추가로 필요하다.

## 하단 탭바 (공통)

4개 탭 화면(홈·메뉴·기록·설정)에 공통으로 들어간다.

- 컨테이너: 배경 `softer`, 위 1px `pressed`, `padding: 8px 8px 26px`
- 각 탭: flex:1, min-height 52px, 세로 정렬, gap 5px
- 아이콘 26×26 라인, 스트로크 약 1.7px, `currentColor`
- 라벨 12px, 비활성 500 / 활성 600, letter-spacing −0.1px
- 활성 색 `tab-active`, 비활성 `body` — **면·배지·밑줄 없이 틴트만**

아이콘: 오늘 = 오니기리, 메뉴 = 책, 기록 = 시계, 설정 = 슬라이더.

네 아이콘 모두 26px 박스 안에서 아트워크 크기(약 20px)와 스트로크 굵기를 맞춰 광학적으로 통일했다. viewBox를 각각 다르게 잡아 크기를 맞췄으므로 SVG를 옮길 때 viewBox 값을 그대로 가져가야 한다.

설정 아이콘의 동그라미는 `var(--softer)`로 채운다 — 채우지 않으면 슬라이더 선이 원을 관통한다.

**기록 탭은 아직 확정되지 않았다.** 두 방향이 있다 — 영수증을 날짜순으로 쌓는 아카이브(`7b` 스케치), 그리고 통계형 기록(위 [인터랙션 프로토타입 B](#b-기록-탭-신규-제안)). 둘 중 택하거나 결합하는 결정이 남아 있다.

## Accessibility

- 터치 타깃 최소 44pt — 예외 없음
- 본문 15pt 이상
- 텍스트 대비 WCAG AA 이상 — `body` 라이트 **7.27:1** / 다크 **7.20:1**, `tab-active` 라이트 4.63:1 / 다크 **5.21:1**. 전 조합을 실측 검증했고 미달은 0건이다
- `mute`(라이트 3.25:1 / 다크 3.48:1)는 비활성·플레이스홀더 전용. 읽어야 하는 텍스트에 쓰지 않는다 — **의도된 저대비이지 실패가 아니다**
- CTA 라벨은 `on-primary`(잉크)를 쓴다. 흰 글자는 orange-600 위에서 3.56:1로 미달한다
- 아이콘 전용 버튼(닫기, TTS, 뷰 전환, 뒤로)에 접근성 라벨 필수
- 한 화면 = 하나의 명확한 주요 행동

## 변경 이력

### Figma 라이브러리 구축에 따른 동기화

이 문서를 Figma로 옮기면서 측정하고 검증한 결과를 반영했다. 화면 레이아웃 명세는 바뀌지 않았고, **토큰·타이포·대비 수치만** 갱신했다.

**접근성 — 실측 후 수정**

| 항목 | 이전 | 현재 |
|---|---|---|
| `on-primary` | `#FFFFFF` (orange-600 위 **3.56:1, AA 미달**) | `#1D1D21` 양 모드 (**4.72:1**) |
| `body` 대비 (라이트) | 8.3:1로 표기 | 실측 **7.27:1** |
| `tab-active` 대비 (다크) | 5.55:1로 표기 | 실측 **5.21:1** |
| `mute` 대비 | 3.4:1 | 실측 3.25:1 / 3.48:1 |
| status 4색 | 미정의 | 모드별 값 추가 — 단일 hex로는 양 테마 AA 불가 |

**토큰 추가** — `on-ink`(잉크 면 위 글자, `ink`와 함께 반전). `DESIGN.md`가 `on-dark`를 참조만 하고 정의하지 않았던 것을 정식화했다. 고정값으로 두면 다크에서 흰 배경에 흰 글자가 된다.

**서체** — Pretendard → **Pretendard JP**. 일반 Pretendard에 한자가 없어 학습 카드가 비어 렌더링된다.

**타이포** — 역할별 스타일 이름을 부여하고 `DESIGN.md`에 정식 등록했다. 이 문서에만 있던 15px 본문, 17px 카드 제목, 18/600 이름, 44px 단어, 26px 뜻, 12px 탭 라벨이 모두 시스템 스타일이 되었다(14종 → 22종). 구현 시 값을 직접 쓰지 말고 스타일을 참조한다.

**CTA 높이** — `button-primary`의 세로 패딩을 20px에서 16px로 고쳐 이 문서의 56px과 일치시켰다.

**세그먼트 그림자 제거** — 이 문서가 지정하던 `0 1px 3px shadow`를 뺐다. `DESIGN.md`의 "Level 1이 시스템의 유일한 그림자이며 `card`와 `toast` 전용" 규칙이 우선한다. `soft` 트랙 위의 흰 면만으로 활성 상태가 충분히 읽힌다.

**토큰 2개 추가** — 이 문서가 쓰는데 `DESIGN.md`에 없던 값을 정식 등록했다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `{rounded.receipt}` | 4px | 영수증 전용. 이 반경 하나가 "종이" 신호를 전담하므로 다른 어디에도 쓰지 않는다 |
| `{spacing.2xl}` | 24px | 히어로·보상 카드 세로 패딩, 그룹 간격의 좁은 쪽 |

이로써 이 문서가 참조하는 색·타이포·반경·간격이 전부 `DESIGN.md`에 정의되어 있다. 값을 직접 쓰지 말고 토큰을 참조한다.

### 남은 불일치

- **아이콘.** 탭바 4종·뷰 전환·셰브론이 Figma에서는 임시 도형이다. 프로토타입 인라인 SVG를 추출해 벡터로 넣어야 하며, 26px 박스 · 1.7px 스트로크 · 라운드 캡의 광학 통일을 유지한다.
- **화면별 일회성 패딩.** 예문 블록 `16 18`, 진행 헤더 `14 12 0`, 범위 칩 `9 14` 같은 값은 4px 그리드 위에 있지만 이름 붙은 토큰은 아니다. 특정 화면의 레이아웃 값이지 시스템 값이 아니라고 보아 그대로 두었다 — 토큰으로 올리면 스케일이 의미를 잃는다.
