# Handoff: Onikan (오니칸) — 일본어 단어 학습 앱 핵심 4화면

## Overview

Onikan은 출퇴근·자투리 시간에 일본어 단어/한자를 학습하는 모바일 앱이다. 하루 12–20단어를 학습하면 '오니기리 재료'를 하나 받고, 재료 4개가 모이면 레시피(오니기리 1종)가 완성되어 도감에 수집된다. 복습 스케줄은 FSRS(간격 반복)가 관리한다.

타겟은 30–40대 직장인. 톤은 "깔끔하고 믿음직한 데일리 리추얼"이며, 귀여움은 마스코트 일러스트 한 점으로만 표현하고 UI 자체는 무채색 중심으로 조용하게 유지한다.

이 핸드오프는 확정된 4개 화면을 담는다.

| # | 화면 | 확정안 |
|---|---|---|
| 1 | 학습 세션 | `1b` — 리콜 흐름 + 2단계 평가 |
| 2 | 학습 완료 결과 + 영수증 | `7a` — CTA가 영수증을 발행 |
| 3 | 홈 | `3a` — 오늘 학습 / 회독 세그먼트 |
| 4 | 메뉴(도감) | `5a` — 목록 ↔ 그리드 전환 |

기술 스택은 Expo · React Native를 전제로 한다.

## About the Design Files

이 번들의 `Onikan Study.dc.html`은 **HTML로 만든 디자인 레퍼런스**다. 의도한 외형과 동작을 보여주는 프로토타입이며, 그대로 가져다 쓰는 프로덕션 코드가 아니다.

해야 할 일은 이 HTML 디자인을 **대상 코드베이스의 기존 환경(Expo · React Native)에서 그 환경의 관례와 라이브러리로 다시 만드는 것**이다. HTML/CSS를 복사하지 말고, React Native의 `View`/`Text`/`Pressable`/`FlatList`와 프로젝트의 기존 컴포넌트·테마 시스템으로 재구성한다.

파일을 열면 여러 개의 아이폰 프레임이 나열되어 있다. 각 프레임 왼쪽 위의 `1b`, `3a`, `5a`, `7a` 배지가 이 문서의 화면 번호와 대응한다. 확정되지 않은 다른 배지(`1a`, `2a`, `2b`, `4a`, `4b`, `7b`)는 검토 과정에서 만든 대안이므로 **구현 대상이 아니다** — 판단 근거를 확인할 때만 참고한다.

프레임 오른쪽의 회색 패널은 각 안의 설계 의도를 적은 주석이다. 구현 시 "왜 이렇게 되어 있는가"를 알고 싶을 때 읽으면 된다.

**`plate`가 테마 고정인 이유:** 마스코트·오니기리 일러스트가 검정 선화라서 다크에서 배경까지 어두워지면 그림이 사라진다. 흰 선화 버전 에셋이 준비되면 그때 테마별로 전환한다.

**`tab-active`가 테마별로 다른 이유:** 12px 라벨이 AA(4.5:1)를 넘어야 해서, 라이트에서는 orange-700 `#C2410C`(4.63:1)를 쓴다. 다크는 `#EA580C`가 5.55:1로 통과한다.

### 컬러 사용 규칙 (엄수)

- **화면당 orange는 정확히 하나.** 주요 액션에만. 탭바의 활성 표시는 '위치 표시'로 간주해 예외로 허용하되, 그 화면의 주요 CTA와 동시에 존재할 때만 성립한다. 오버레이가 뜨면 아래 CTA를 **렌더하지 않는다**(투명도로 가리지 말 것).
- **lime `#A3E635`는 보상 획득 순간에만.** 체크 배지, 방금 채워진 진행 칸의 페이드아웃. 그 외 어디에도 쓰지 않는다.
- **`mute`는 잠김·플레이스홀더 전용.** 일반 캡션에 쓰면 대비 미달이다. 조용하게 보이고 싶으면 색이 아니라 크기·굵기로 낮춘다.
- 금지: 그라데이션, 텍스트 그림자, 카드 안 카드(중첩), 뱃지·라벨에 브랜드색.

### 간격 · 반경 · 그림자

- 화면 좌우 여백: **20px**
- 카드 내부 패딩: 18–24px
- 그룹 간 간격: 24–28px (박스로 감싸지 말고 여백으로 나눌 것)
- 반경: 카드 **24px**, 타일 14–18px, 버튼·필·진행바 **999px**, **영수증만 4px**
- 카드 그림자: `0 6px 14px var(--shadow)` — 이것 하나만 쓴다
- 터치 타깃: 최소 **44pt**, 탭바 아이템 52pt, 평가 버튼 60pt

**4px 반경은 영수증 전용이다.** 이 반경 하나가 "종이"라는 신호를 전담하므로 다른 어디에도 쓰지 않는다.

## Screens / Views

### 1. 학습 세션 (`1b`)

**Purpose.** 하루치 단어를 리콜(회상) → 공개 → 자가평가 순으로 학습한다. 앱의 핵심 화면.

**해결한 문제.** 이전 버전은 카드 앞면에 뜻과 예문이 즉시 노출되어 '떠올리기' 단계가 없었고, 평가 버튼이 4개(모름·어려움·앎·쉬움)라 누르기 전 망설임이 컸다.

**Layout.** 세로 flex. 상단 상태바 → 진행 헤더 → 카드(flex:1) → 하단 액션 영역. 좌우 20px.

**진행 헤더** (`padding: 14px 12px 0`)
- 왼쪽: 닫기 버튼 44×44, 아이콘 24px, 색 `body`
- 가운데: 12칸 세그먼트 진행바. 각 칸 `flex:1`, height 4px, radius 999px, gap 4px. 채워진 칸 `ink`, 빈 칸 `pressed`
- 오른쪽: "9개 남음" 13px/600 `body`, 오른쪽 패딩 16px

**카드** (`canvas`, radius 24px, `0 6px 14px shadow`, padding `40px 24px 24px`)

앞면:
- 일본어 단어 44px/700 중앙 정렬
- 10px 간격
- 발음 행: 읽기(18px/500 `body`) + TTS 버튼(44×44 원형, 배경 `soft`, 아이콘 20px)을 gap 10px로 가로 배치
- 하단(`margin-top:auto`): 36px 점선 원(1.5px dashed `pressed`) + "탭해서 뜻 확인" 15px `body`, gap 10px

뒷면(카드 또는 "뜻 보기"를 탭한 뒤):
- 앞면 요소는 그대로 유지되고 아래로 이어붙는다(32px 간격)
- 뜻 26px/700 중앙
- 20px 간격
- 예문 블록: 배경 `soft`, radius 18px, padding `16px 18px`. 일본어 16px/26px `ink`, 한국어 14px/20px `body`, gap 8px
- "단어 상세 ›" 텍스트 버튼 14px/600 `body`, min-height 44px

**하단 액션** (`padding: 20px 0 28px`)

앞면 — 주요 액션 하나:
- "뜻 보기" 전체폭, min-height 56px, radius 999px, `primary` / `on-primary`, 18px/600

뒷면 — 2단계 평가, gap 10px:
- **아직이에요** — flex:1, min-height 60px, radius 999px, 배경 투명, 테두리 1.5px `pressed`, 글자 `ink` 17px/600
- **외웠어요** — flex:1, min-height 60px, radius 999px, 배경 `ink`, 글자 `softer` 17px/600

**평가가 2단계인 근거.** 4단계에서 망설임의 원인은 "어려움/앎"의 자기판단 경계가 모호한 것이었다. 사용자는 "알겠다/모르겠다"만 즉각 판단하면 된다. 라벨은 둘 다 *현재 내 상태*를 말하는 형태로 통일했다("또 볼래요" 같은 의사 표현은 시제 축이 달라 나란히 비교되지 않는다).

**다음 복습 시점(10분 뒤/3일 뒤)은 버튼에 표시하지 않는다.** 시스템 언어가 판단을 다시 늘리기 때문. 대신 결과 화면에서 "오늘 외운 12개는 내일 다시 확인해요" 한 줄로 회수한다.

**남는 과제.** FSRS에 Hard/Easy 신호가 없어 초반 간격 추정이 거칠다. 첫 2주는 보수적 간격으로 시작하고, 필요하면 '외웠어요' 롱프레스에 '완전 쉬움'을 숨겨 두는 방식으로 보완한다.

**Copy.** 상단 "9개 남음" · 앞면 "탭해서 뜻 확인" / "뜻 보기" · 뒷면 "단어 상세 ›" / "아직이에요" / "외웠어요"

### 2. 학습 완료 결과 + 영수증 (`7a`)

**Purpose.** 세션을 닫으면서 보상(재료)을 전달하고, 영수증을 발행해 리추얼의 마침표를 찍는다. **이 영수증이 서비스의 시그니처다.**

**Layout — 결과 화면.** 좌우 20px, 위 32px.

1. 오버라인 "오늘의 학습" 12px/500 `body`, letter-spacing 1.4px, uppercase
2. 8px
3. "다 했어요" 32px/700
4. 28px
5. **보상 카드** — `canvas`, radius 24px, `0 6px 14px shadow`, padding `24px 20px`, 가로 flex gap 18px
   - 왼쪽: 88×88 타일 radius 18px 배경 `plate`, 마스코트 이미지 74×74 `object-fit:contain`, `position:relative`
     - 우하단 −6px/−6px에 30×30 원형 배지, 배경 `#A3E635`, 안에 체크 글리프(24px 프레임을 0.8배 스케일, 색 `#1D1D21`)
   - 오른쪽: 오버라인 "새 재료" / 재료명 26px/700 / "사장이 재료를 하나 건넸어요" 15px `body`, gap 6px
6. 28px
7. **레시피 진행** — 제목 20px/600 + "1 / 4" 13px/500 `body` (space-between) / 4칸 진행바(height 8px, gap 8px, 채움 `ink`, 빈칸 `pressed`) / "완성까지 세 번 남았어요" 15px `body`, gap 12px
8. 28px
9. **요약 2행** — 각 행 `padding: 14px 0`, 위아래 1px `pressed` 구분선. 라벨 15px `body` ↔ 값 17px/600 tabular-nums
   - "새로 배운 단어" 12 / "아직이라고 표시한 단어" 3
10. 16px
11. "오늘 외운 12개는 내일 다시 확인해요." 15px/22px `body`
12. `margin-top:auto` → CTA 영역 `padding: 20px 0 28px`
    - **"영수증 받고 마치기"** 전체폭 56px, `primary`

**보상이 숫자보다 위에 있는 이유.** "내가 뭘 얻었나"가 "내가 몇 개 했나"보다 앞선다. 숫자(12·3)는 두 줄로 강등한다.

**애니메이션 (결과 화면 진입 시)**
- 보상 카드: `riseIn` — `translateY(10px)` + `opacity 0` → 0/1, **0.4s ease**
- 체크 배지: `pop` — scale 0.6→1.08→1, opacity 0→1, **0.45s ease, 0.25s 지연**
- 진행바 첫 칸: `limefade` — 배경이 `#A3E635`에서 시작해 55% 지점부터 `ink`로 전환, **1.2s ease, 0.3s 지연**

`limefade`가 라임의 유일한 사용처 중 하나다. 방금 채워진 칸만 잠깐 라임이었다가 잉크로 가라앉는다.

**Layout — 영수증 오버레이.**

CTA를 누르면 상태 `receipt = true`. 이때:

> **결과 화면의 CTA 영역을 렌더에서 제외한다.** 투명도나 z-index로 가리면 안 된다. 스크림 뒤로 오렌지가 비쳐 화면에 오렌지가 둘이 되고, 위에 겹친 흰 글자와 충돌한다.

- 스크림: `position:absolute; inset:0`, `rgba(19,19,22,.82)`, `dimIn` **0.2s ease**
- 영수증 종이: 상단 정렬, `padding: 56px 26px 0`, 배경 `canvas`, **radius 4px**, padding `30px 24px 26px`
  - 애니메이션 `printOut` — `translateY(-101%)` → `0`, **0.9s `cubic-bezier(.22,.61,.36,1)`**. 위에서 인쇄되어 내려오는 느낌
  - 내용: "ONIGIRI SHOP" 15px/600 letter-spacing 3px 중앙 → 일시 13px `body` tabular-nums → 1px dashed `pressed` → 3행 명세(새로 배운 단어 12 / 아직이라고 표시 3 / 받은 재료 + 라임 체크 배지 20px) → 1px dashed → 참치마요 1/4 + 4칸 진행바(height 6px) → "오늘 외운 12개는 / 내일 다시 확인해요." 중앙 → "THANK YOU · 24일째" 12px letter-spacing 2.4px `body`
  - 행 사이 구분선은 1px `soft`, 섹션 경계만 1px dashed `pressed`
- 하단 액션 `padding: 20px 26px 34px`, gap 10px
  - "이미지로 저장" / "공유" — 각 flex:1, 52px, radius 999px, 배경 `canvas`, 글자 `ink` 16px/600

**Copy.** "다 했어요" · "새 재료" · "사장이 재료를 하나 건넸어요" · "완성까지 세 번 남았어요" · "오늘 외운 12개는 내일 다시 확인해요." · "영수증 받고 마치기" · 영수증 푸터 "THANK YOU · 24일째"

**"약 6분"이 필요한 이유.** 출퇴근·자투리 시간 사용자가 시작 전에 가장 알고 싶어 하는 정보다.

4개 탭 화면(홈·메뉴·기록·설정)에 공통으로 들어간다.

네 아이콘 모두 26px 박스 안에서 아트워크 크기(약 20px)와 스트로크 굵기를 맞춰 광학적으로 통일했다. viewBox를 각각 다르게 잡아 크기를 맞췄으므로 SVG를 옮길 때 viewBox 값을 그대로 가져가야 한다.

설정 아이콘의 동그라미는 `var(--softer)`로 채운다 — 채우지 않으면 슬라이더 선이 원을 관통한다.

## Interactions & Behavior

### 학습 세션 (1b)

| 트리거 | 결과 |
|---|---|
| 카드 탭 또는 "뜻 보기" | `revealed = true`. 뜻·예문·평가 버튼 노출, "뜻 보기" 버튼 제거 |
| "아직이에요" | FSRS `Again`. 이번 세션 큐 뒤쪽에 다시 삽입. 다음 카드로, `revealed = false` |
| "외웠어요" | FSRS `Good`. 다음 카드로, `revealed = false`. 진행 카운트 +1 |
| TTS 버튼 | 발음 재생. **카드 탭 이벤트가 버블링되지 않도록 정지시킬 것** (앞면에서 실수로 공개되는 것을 막는다) |
| "단어 상세 ›" | 단어 상세 화면으로 이동 |
| 닫기(✕) | 세션 종료 확인 후 홈으로 |

카드 앞→뒤 전환은 뒤집기가 아니라 **아래로 이어붙이는 방식**이다. 앞면 요소(단어·발음)는 위치를 유지한 채 그 아래에 뜻·예문이 추가된다. 사용자가 방금 본 단어를 잃지 않는다.

### 결과 + 영수증 (7a)

| 트리거 | 결과 |
|---|---|
| 화면 진입 | `riseIn` / `pop` / `limefade` 3개 애니메이션 (위 명세 참조) |
| "영수증 받고 마치기" | `receipt = true`. 결과 CTA 렌더 제외 → 스크림 `dimIn` → 영수증 `printOut` |
| "이미지로 저장" | 영수증을 이미지로 렌더해 사진첩 저장 |
| "공유" | OS 공유 시트 |
| "닫기" | `receipt = false` → 홈으로 이동 |

영수증은 기록 탭에 날짜순으로 보관되므로 '닫기'의 심리적 비용이 없다. (기록 탭 전체 설계는 이번 범위 밖 — 대안 `7b` 프레임에 방향성만 스케치되어 있다.)

### 홈 (3a)

| 트리거 | 결과 |
|---|---|
| 세그먼트 "오늘 학습" / "회독" | `homeMode` 전환. 카드 내용 + 하단 블록 + CTA 문구가 함께 바뀜 |
| CTA | 해당 모드로 학습 세션 진입 |
| 레시피 진행 블록 탭 | 메뉴 탭의 해당 레시피로 이동 |
| 회독 범위 칩 | 범위 변경 (칩 선택 상태) |

### 메뉴 (5a)

| 트리거 | 결과 |
|---|---|
| 뷰 전환 아이콘 | `menuView` 전환(list ↔ grid). **선택을 기기에 저장하고 다음 진입 시 복원** |
| "이어서" | 학습 세션 진입 |
| 목록 행 / 그리드 타일 탭 | 레시피 상세 (완성·진행 중만. 잠김은 비활성) |

### 공통

- 모든 버튼 press 상태: 배경을 한 단 어둡게(라이트) / 밝게(다크). 스케일 변형이나 투명도 전체 적용은 쓰지 않는다.
- 테마: 시스템 설정을 따르되 설정에서 수동 전환 가능.
- 애니메이션은 `prefers-reduced-motion`에서 전부 비활성화하고 최종 상태만 렌더한다.

## Accessibility

- 터치 타깃 최소 44pt — 예외 없음

- 한 화면 = 하나의 명확한 주요 행동
