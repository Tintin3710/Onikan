## 6. 개선 후보 → 다음 단계 입력

SEED는 "고칠 곳"에만 참고한다. 오니칸 고유 요소(주황 브랜드, 라임 = 보상 전용, 잉크 = 주요 액션, 사장 캐릭터 톤)는 유지한다. SEED의 구체 규칙은 착수할 때 공식 문서로 확인한다.

| # | 문제 (근거) | 영향 | SEED 참고 후보 |
|---|---|---|---|
| P1 | 레이아웃·간격 규칙 충돌, 스케일 밖 간격 90개 이상 (§1, §2) | 화면 불일치의 주원인 (§4) | 간격·레이아웃 규칙 정의 방식 |
| P2 | 타이포 이름 체계 불일치, 빠진 역할 6개 (§1) | 직접 쓴 fontSize 47개 | 타이포 스케일 이름 체계 |
| P3 | 코드에만 있는 색·레이아웃·모션 토큰, 램프 밖 색 (§1) | 문서가 정본 역할을 못 함 | 기본값(팔레트) → 용도(배경·글자·테두리) 2단계 토큰 구조 |
| P4 | 공용 컴포넌트 없음 13개, 중복·미사용 7개 (§3) | 화면 고유 레이아웃이 매번 새로 만들어짐 | 컴포넌트 문서 형식 (구조·변형·상태·사용 규칙) |
| P5 | 정본 우선순위 반대, 오래된 문장, Code Connect 없음 (§5) | 기준이 둘 | 차용 불필요 — 오니칸 자체 운영 규칙 |

### 이력서에 지금 쓸 수 있는 것 / 아직 못 쓰는 것

| 지금 근거 있음 | 개선 후 쓸 수 있음 |
|---|---|
| 토큰(색·타이포·간격·반경·그림자)을 정의하고 개발자와 앱에 적용 | 화면 불일치 원인을 진단하고 규칙을 재정의해 불일치 n% → n% |
| 접근성 기준(AA)으로 색 역할 재정의(D-3) | 공용 컴포넌트 n개 정리, 직접 쓴 값 n개 → n개 |
| 결정 로그(D-n, O-n)로 근거 관리 | 정본 우선순위 단일화 + 자동 검사로 운영 |
